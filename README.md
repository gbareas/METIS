# METIS — ML for high-pressure transcritical flow simulations

[![CI](https://github.com/gbareas/METIS/actions/workflows/ci.yml/badge.svg)](https://github.com/gbareas/METIS/actions/workflows/ci.yml)
![Python](https://img.shields.io/badge/python-3.10%2B-blue)
![Docker](https://img.shields.io/badge/demo-docker%20run-2496ED)
[![License: MIT](https://img.shields.io/badge/license-MIT-green)](LICENSE)

**METIS** (**M**achine-learning **E**ngine for **T**ranscritical **I**nsight
& **S**tatistics) is a tested Python framework that takes large (multi-GB per case)
direct numerical simulation (DNS) output of supercritical-CO₂ channel flow
and turns it into validated physics features, reproducible ML experiments
and reports. It also includes a small agent that decides when a fast
neural-operator surrogate can be trusted and when to fall back to the
full simulation.

![METIS summary figure](docs/summary.png)

<sub>**Left:** on 9 real DNS cases, the pressure regime is recovered from bulk
dimensionless groups and the thermal regime from wall-normal turbulence
profiles (leave-one-case-out accuracy, chance = 1/3). **Right:** the router
trusts the surrogate only inside its training envelope and sends anything
past the pseudo-critical point to the DNS database. Both panels are
regenerated by `metis demo`.</sub>

## At a glance

| | |
|---|---|
| **Problem** | High-fidelity simulations of supercritical fluids are expensive, and ML surrogates for them fail silently out of distribution. Each new study used to rebuild its own analysis pipeline. |
| **What it does** | Ingests and validates simulation snapshots, computes standard physics (dimensionless groups, spectra, POD), builds cached feature datasets, trains and evaluates models, and writes reports, all from one `metis` CLI. |
| **Results** | Found which physics features carry each operating parameter, frozen as a regression benchmark. Two documented negative results: autoencoders did not beat linear PCA/POD on this data. An out-of-distribution rule that routes queries away from a surrogate where it is known to fail. |
| **Engineering** | ~250 automated tests, CI on every push, Docker image with a one-command demo, MLflow tracking, fingerprinted dataset caching and provenance on every artifact. |
| **Stack** | Python, NumPy, SciPy, h5py, PyTorch, scikit-learn, MLflow, matplotlib, Docker, GitHub Actions, Claude API (explanation layer only). |

Small sample sizes are stated as such: the regime results rest on 9
training cases and the routing rule on 2 out-of-distribution cases, so
both are treated as frozen, testable findings rather than general claims.
The full research log, including what did not work, is in
[`FINDINGS.md`](FINDINGS.md).

## Run it in one command

No DNS data, GPU or API key needed. With Docker:

```bash
git clone https://github.com/gbareas/METIS && cd METIS
docker build -t metis .
docker run --rm -v "$PWD/demo_output:/out" --user "$(id -u):$(id -g)" metis
```

Or with Python ≥ 3.10:

```bash
pip install -e ".[report]"
metis demo            # writes demo_output/
```

The demo runs in a few seconds and does three things:

1. **Pipeline on a synthetic case.** Generates a small DNS-shaped HDF5
   file (random fields, not physics) and runs ingest → validate → physics
   analysis → report on it, to show the framework end to end.
2. **The frozen `regime-v1` benchmark on real-derived data.** Re-runs it
   from a committed 60 KB feature sample extracted from the 11 real DNS
   cases, and checks all 7 frozen checks pass (exit code 1 if not).
3. **The router's confidence policy.** Scores 8 curated operating points
   and shows where each would be routed. Only the decision runs here: the
   surrogate checkpoint and the DNS fields it dispatches to are not in
   this repository.

Outputs: `summary.png`, `regime_v1.json`, `router_decisions.json` and
Markdown reports under `reports/`. CI builds the image and runs the demo
on every push.

## How it fits together

A reusable analysis and physical-discovery layer that sits **downstream**
of the group's DNS solver, **RHEA** (*Reproducible Hybrid-architecture
flow solver Engineered for Academia*), for high-pressure transcritical
channel flow. RHEA generates the physics and stays upstream and
authoritative; METIS standardises how its output is ingested, validated,
turned into features, analysed, modelled, and reported — so a new study
configures the framework instead of rebuilding the pipeline.

## What it can do

- **Ingest & validate** RHEA snapshots and homogeneous-plane slices into
  `DNSCase` / `SliceCase`; catch bad or incompatible data before analysis
  (`metis.data.{ingestion,registry,validation}`).
- **Standard physics** — bulk dimensionless groups, wall friction
  Reynolds numbers, 1-D wavenumber spectra, snapshot POD — cross-checked
  bit-for-bit against published results (`metis.features`).
- **Regime discovery**, frozen as the reproducible `regime-v1` benchmark
  (`metis benchmark regime-v1`; see `FINDINGS.md`).
- **One analysis API** — `metis analyze physics|spectra|pod|
  regime-features <case>` — each producing a standard, validated,
  saveable result.
- **Cached feature datasets** so re-running an evaluation doesn't re-read
  raw DNS (`metis dataset build`).
- **Reproducible ML** — leakage-safe preprocessing, a small trainer,
  PCA/autoencoder representation models, physics-aware evaluation, MLflow
  experiment tracking, and a reporting layer (`metis report`).
- **`metis` CLI** and an **artifact registry** tying it together.
- A separate **router-agent module**: OOD-gated routing
  between a neural-operator surrogate and the DNS database, with a
  single-tool LLM explanation layer. See below.

```mermaid
flowchart LR
    A[DNS snapshots<br/>HDF5] --> B[ingest +<br/>validate]
    B --> C[physics features<br/>bulk, spectra, POD]
    C --> D[cached feature<br/>datasets]
    D --> E[models<br/>PCA, autoencoders]
    E --> F[physics-aware<br/>evaluation]
    F --> G[reports +<br/>frozen benchmarks]
```

Module-by-module detail: [`docs/architecture.md`](docs/architecture.md).

## Install for development

```bash
pip install -e ".[dev]"     # framework + tests; installs the `metis` command
pytest -q                   # ~250 tests, self-contained, a few seconds
```

Optional extras: `ml` (torch, scikit-learn, mlflow), `report`
(matplotlib), `router` + `demo` (the router module), documented in
`pyproject.toml`.

## Running on real DNS data

The DNS data itself is not public. The committed results, the feature
sample and the router's OOD numbers were derived from the research
group's simulations and earlier studies, and are included for research
purposes. With access to it (the standard `raw/` `processed/`
`processed_slices/` layout under one root — point METIS at it with
`--data-root`, `$METIS_DATA_ROOT`, or `data.root` in
`configs/default.yaml`):

```bash
export METIS_DATA_ROOT=/path/to/dns_data
metis cases list
metis case validate case01
metis analyze physics case01
metis benchmark regime-v1
metis report regime-v1 --from results/regime_v1.json
metis report i2b-representation --from results/   # bundles the i2b_*.json study outputs
```

## Router agent

![Router demo](docs/router_demo.gif)

Routes a transcritical query to a fast neural-operator surrogate **or**
the DNS database based on a *validated* out-of-distribution confidence
signal (blind surrogate error tracks the cold-wall temperature ratio
crossing the pseudo-critical point), and explains the decision in plain
language. The LLM never makes the routing decision. Full write-up,
architecture diagram, and the link to the group's earlier research:
**[`docs/router_agent.md`](docs/router_agent.md)**.
